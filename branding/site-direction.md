# Site Direction

The public portfolio site should be an index of accessible work, not a synthetic landing page.

## Current Direction

- Use the shared theme before adding site-only color.
- Keep the page quiet enough that 같이가계, NULSIGHT remain the primary evidence.
- Prefer real links, project summaries, and implementation notes over decorative diagrams.
- Avoid orbit diagrams, fake dashboards, abstract pulsing panels, and decorative motion that does not show a real interaction.
- The site may feel polished and technically capable, but it should not pretend to be a SaaS product, generic landing page, or fictional command center.

## Visual Direction Decision

The site should move toward a purposeful neo-brutal portfolio index.

The ratio is:

- 70% accessible work index
- 20% exposed system structure
- 10% restrained web interaction demonstration

This gives us room to add sharper blocks, visible grids, hard outlines, and signal-like accents without turning the page into a poster.

Flat design remains the base layer. Neo-brutalism and Nothing-inspired details are additive layers.

## First Screen Rule

The first screen should show project access and real work evidence.

- Do not lead with a large self-introduction hero.
- Show 같이가계, NULSIGHT, and repository/site access quickly.
- Keep implementation evidence visible without making a fake dashboard.
- Use one clear primary route and a few direct secondary links.

## What To Show

- Direct links to the live site, 같이가계, NULSIGHT, and repository.
- Short project descriptions that explain what can be opened and tested.
- A small implementation section for real web techniques used in the apps.
- Shared-system notes only when they help a collaborator understand the monorepo.

## Demonstration Budget

Allowed:

- responsive project preview layouts
- subtle section transitions
- hover/focus states that show interaction craft
- small live-feeling details tied to real project links or implementation notes
- exposed layout or system diagrams when they represent the real monorepo
- signal-like UI details when they indicate focus, selection, active project, or navigation

Avoid:

- decorative console panels
- fake status feeds
- abstract orbit or network diagrams
- metrics that do not come from the actual projects
- long slogans that could describe any portfolio
- dot-matrix decoration with no state or interaction meaning
- neo-brutalist color blocks that compete with project evidence

## Color And Motion

- The site is dark-mode-first, matching the rest of the monorepo.
- Default to `themes/theme.*` tokens.
- Site-local colors require a note here explaining their role.
- Current decision: the site uses the shared `#C8D0D3`, `#735587`, `#91EDFC` palette through theme tokens and does not add a site-only fourth accent.
- Do not add a light landing-page variant unless `theme-principles.md` is updated first.
- Motion should demonstrate interaction state, not fill empty space.
- Reduced-motion behavior should remain boring and correct.
- Cyan is reserved for high-signal states; violet is atmospheric; mist is structural.

## Copy Tone

- Korean-first labels for navigation and section names.
- English technical terms are fine inside chips when they are the actual implementation terms.
- Avoid slogan-like claims. Prefer concrete statements that can be checked by opening the apps.
- A section should earn its text through one of three roles: link, project explanation, or implementation evidence.
- Use development order when listing projects: 같이가계, NULSIGHT.
- Project summaries should read like portfolio notes: product type, implementation scope, and verifiable link.
- Avoid generic portfolio verbs such as "showcase", "explore", "experience", or "demonstrate" unless a real interaction is named.
- Prefer "로비, 덱 편집, 듀얼 화면을 연결했다" over "TCG 흐름을 구성했다".
- Project card date labels should follow `branding/project-timeline.md`.
